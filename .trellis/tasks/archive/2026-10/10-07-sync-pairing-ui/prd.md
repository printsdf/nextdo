# 优化同步配对UI：连接串优先与多端导出配对

## Goal

将设置页重构为单一连接串粘贴优先，收敛手填表单至高级设置；已连接设备提供连接串一键复制与扫码配对展示，补齐多端配对闭环。

## Background & Pain Points

1. **未连接状态认知负担重**：
   - 目前设置页默认展示两个输入框：「服务器地址」和「owner token 或连接串」。
   - 虽然底层代码已支持粘贴连接串（`<server>|<token>` 或 `nextdo://...`），但用户看到两个输入框且提示“填写你的同步服务器地址与 owner token”时，直觉上仍认为需要逐一手动输入两项配置。
   - 应该以“单一连接串”为主路径，一行输入即可完成连接。

2. **多端配对缺乏导出能力**：
   - 已经连接好云同步的设备（如 Desktop 或第一台手机），在设置页仅显示只读的 backendUrl 和 endpoint，没有任何导出功能。
   - 用户为第二台设备配对时，无法从已连接设备获取连接串或二维码，多端协同闭环缺失。

## Requirements

### 1. 未连接状态（Disconnected View）
- **单一连接串主输入框**：
  - 界面默认展示单一输入框，占位文案提示支持连接串格式（如 `粘贴连接串（例如 https://example.com|token 或 nextdo://...）`）。
  - 用户粘贴完整连接串后点击「连接」，自动解析出服务器地址与 Token 并发起验证。
- **高级设置收敛**：
  - 保留「高级设置 / 手动输入」折叠项（默认折叠）。
  - 展开后提供分离的「服务器基础地址」、「后端地址」、「同步流地址」及「owner token」手动输入框，满足自定义反代等高级场景需求。
- **校验与错误处理**：
  - 保持原有的错误提示文案与拦截逻辑不变（空地址、无效 URL、空 Token、401 凭证错误、网络不可达等）。

### 2. 已连接状态（Connected View）
- **一键复制连接串**：
  - 提供「复制连接串」按钮。
  - 点击后将当前设备的连接串（标准明文格式 `<serverAddress>|<token>`）复制到系统剪贴板。
  - 复制成功后提供视觉反馈（按钮文本临时切换为「已复制」2 秒）。
- **扫码配对展示**：
  - 提供「扫码配对」按钮 / 区域。
  - 点击可展开或弹窗展示配对二维码（内容为移动端深层链接 `nextdo://sync?s=<url>&t=<token>`）。
  - 纯前端跨端轻量渲染，兼容 iOS、Android 与 Web/Tauri，无原生黑盒依赖。
  - 附带使用引导文案（例如“使用另一台手机相机或支持应用扫码即可一键配置 Nextdo 同步”）。
- **断开连接保留**：
  - 保留「断开连接」按钮及现有安全逻辑。

### 3. 数据层与状态支持
- `apps/mobile/lib/sync-connection.ts`：
  - 导出 `formatConnectionString(serverAddress: string, token: string): string` 生成 `<base>|<token>` 明文串。
  - 导出 `formatDeepLink(serverAddress: string, token: string): string` 生成 `nextdo://sync?s=...&t=...` 深度链接。
- `apps/mobile/hooks/use-cloud-sync.ts`：
  - 在已连接状态下保留并暴露 `ownerToken`（或派生好的连接串信息），使 UI 层具备导出能力。

## Acceptance Criteria

- [x] **AC-1（连接串为主）**：未连接状态默认只呈现一个连接串输入框，粘贴连接串即可一键成功连接。
- [x] **AC-2（高级设置折叠）**：手动输入选项收纳在折叠项中，展开后可分别输入服务器地址和 Token 并正常连接。
- [x] **AC-3（一键复制）**：已连接状态下点击「复制连接串」，成功调用剪贴板并给出「已复制」反馈。
- [x] **AC-4（扫码配对展示）**：已连接状态下可切换显示二维码，二维码包含合法的 `nextdo://sync` 链接。
- [x] **AC-5（全端单元测试）**：所有新增及改造的逻辑（format 函数、设置页交互、复制与二维码状态）均有单元测试覆盖，且全量测试通过。

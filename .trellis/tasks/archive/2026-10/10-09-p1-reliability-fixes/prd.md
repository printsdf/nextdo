# PRD: P1 可靠性缺陷修复 (跨端设置持久化、习惯时区运算、时钟前台校准)

## 背景与问题陈述
在日常使用和长期运行中，存在三处影响用户体验和数据一致性的关键工程可靠性问题：
1. **桌面端场景与时间设置丢失**：`apps/mobile/lib/engine-context.ts` 在 Web / Tauri 运行时使用了内存存储（`createMemoryStore`），应用重启后用户的过滤场景和设定时间被重置。
2. **习惯挑战周期时区/夏令时偏差**：`packages/db/src/queries/pool.ts` 中的 `habitCycleDay` 采用固定 `day * 86_400_000` 毫秒计算挑战日，在夏令时切换（一天为 23 或 25 小时）或夏令时/冬令时交替时，毫秒漂移会导致日期匹配错误，造成习惯漏打卡或周期天数计算不符。
3. **休眠/后台唤醒后应用时钟未立即校准**：`apps/mobile/hooks/use-app-clock.ts` 仅使用 `setInterval` 驱动每分钟时钟更新。在移动端后台挂起或电脑睡眠唤醒后，计时器暂停，唤醒后仍显示旧时间，导致行动推荐池未及时重新计算。

## 目标与验收标准 (Acceptance Criteria)

### AC1：桌面端与 Web 场景及可用时间设置持久化
- 在 Web 和 Tauri 环境下，`engine-context.ts` 能够通过 `localStorage` 正常持久化读取和写入 `nextdo.settings.engine-context`。
- 如果环境无 `localStorage`（如 node 纯单元测试或沙盒环境），平滑降级到内存存储，不抛出异常。
- 保证重启、刷新后，之前选中的场景及可用时间被准确保留。

### AC2：习惯周期计算基于日历天递增（避免毫秒固定偏移）
- `habitCycleDay` 必须按本地日历天（日历日期运算）进行匹配与天数推导，消除夏令时（DST ±1 小时）造成的跨天误差。
- 增加针对夏令时转换与跨时区边界的单元测试用例，保证无论时区变化，第 1 到 cycleDays 天均能稳定一一映射。

### AC3：应用时钟前台恢复实时校准
- `useAppClock` 在保持每分钟定时轮询的同时，监听 `AppState` 状态变更（移动端 `active`）以及浏览器/窗口事件（`visibilitychange` / `focus`）。
- 当应用从后台唤醒或从睡眠恢复到前台活跃时，立即校准并分发最新 `Date` 实例，触发推荐池及时间敏感视图即时重算。
- 提供对应单元测试验证唤醒事件触发时钟更新。

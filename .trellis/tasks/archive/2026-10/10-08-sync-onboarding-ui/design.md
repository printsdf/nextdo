# Design: 云同步设置引导与连接分流（Sync Onboarding UI）

## 1. 交互与布局设计

### 1.1 模式切换（分流选择器）

在云同步卡片的「未连接」状态下，顶部提供一个分段选择器（Segmented Control / Tab）：
1. **「扫码 / 连接串配对」**（默认，或首选）
   - 目标群体：已有其他设备（如电脑或第一部手机）已连接的用户。
   - 引导文案：“在已连接设备的设置中，点击「扫码配对」或「复制连接串」，在此粘贴即可一键同步。”
   - 核心输入框：单一输入框，Placeholder 为 `粘贴连接串 (nextdo://sync?...)`。
   - 操作按钮：「连接」。
2. **「自建服务器」**
   - 目标群体：自己部署了 Nextdo 同步服务器、首台接入的用户。
   - 引导文案：“首台设备接入无需 Token，连接后将自动免密绑定并生成配对密钥。”
   - 核心输入框：服务器地址，Placeholder 为 `https://nextdo.example.com`。
   - 操作按钮：「连接并绑定」。

### 1.2 「什么是 Token？去哪里找？」指引卡片

在输入区域下方提供一个可折叠或常驻的高亮说明区块（`Card` / `View`）：
- 标题：“💡 什么是 Token？我需要填吗？”
- 内容分三点说明：
  1. **首台设备**：无需寻找 Token。输入自建服务器地址并点击连接，系统将自动认领并生成主人密钥；
  2. **后续设备**：无需手动抄写 Token。在已连接设备上点击「扫码配对」或「复制连接串」直接导入；
  3. **静态配置**：仅当你在部署服务器时通过 `NEXTDO_OWNER_TOKEN` 环境变量指定了静态密钥时，才需要在「高级设置」中手动填写。

### 1.3 高级设置收拢

点击展开「高级设置与自定义路径」：
- 「手动指定 Owner Token」（选填，针对环境变量静态部署）；
- 「自定义反代后端地址 (`/api`)」；
- 「自定义反代同步流地址 (`/sync`)」。

### 1.4 连接与提交流程复用

底层依然完全复用 `useCloudSync` 的 `connect` 接口与 `deriveSyncConfig`：
- 在「连接串配对」模式：调用 `connect({ serverAddress: parsed.serverAddress, token: parsed.token })` 或解析并提交；
- 在「自建服务器」模式：如果用户未在高级设置中填写手动 token，`token` 为空，传给 `connect({ serverAddress, token: '' })`，自动触发已有的 `claimServer` 自动认领流程；若已被他人认领，内联提示友好的错误信息。

## 2. 状态与兼容性

- 若 URL 带来 deep link 参数或 `syncError`，依然无缝处理并在界面显示；
- 之前保存的 `storedConfig` 仍保留预填逻辑；
- 所有现有的单测用例对连接串解析、错误提示、表单禁用的验证继续有效。

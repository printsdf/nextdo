# PRD: 优化云同步设置引导与连接分流（Sync Onboarding UI）

## 1. 背景与痛点

在当前版本中，云同步未连接状态的界面存在严重的使用门槛与心智摩擦：
1. **找不到 Token 的困惑**：未连接界面直接提示并展示「owner token 或连接串」输入框，用户完全不知道什么是 owner token、去哪里找它；
2. **首台设备路径被隐藏**：虽然服务端已支持「首台设备免密一键绑定（Claim-based pairing）」，但「服务器地址」输入框却被藏在折叠的「高级设置与手动输入」中。导致自建用户首台接入时到处找 token，而不知道只需填写服务器地址即可自动认领；
3. **缺乏场景分流与新手引导**：未将「首台自建设备」与「多端设备扫码互联」拆解为清晰的场景化入口，缺乏常驻的帮助说明。

## 2. 目标

1. **场景化分流切换**：在未连接状态提供清晰的双模式切换：
   - **「扫码 / 连接串配对」**（多端互联场景）：引导用户从已配对设备复制连接串，支持单一连接串粘贴快速配对；
   - **「自建服务器」**（首台设备场景）：服务器地址作为一级主要输入框，文案明确告知“首台接入无需 Token，自动免密绑定”；
2. **常驻引导解答「Token 是什么？去哪找？」**：
   - 提供直观的指引说明卡片：
     - **首台设备**：无需寻找 Token，填入服务器地址直接连接，系统自动生成密钥；
     - **后续设备**：无需寻找 Token，在已连接设备上点击「扫码配对」或「复制连接串」；
     - **环境变量部署**：仅在服务器部署指定了 `NEXTDO_OWNER_TOKEN` 时，才需在高级设置中手动输入该 Token；
3. **收拢高级设置**：仅保留非标准反代路径与可选的手动静态 Token 输入，不干扰主流流程；
4. **保持向后兼容与测试完备**：已有连接串解析、`deriveSyncConfig`、首次免密认领（auto-claim）逻辑不变，单测全绿。

## 3. 验收标准

- [ ] 未连接视图支持「扫码/连接串配对」与「自建服务器」两种模式分流切换；
- [ ] 「自建服务器」模式下，服务器地址为主输入框，界面明确引导“首台设备免密自动绑定，无需填 Token”；
- [ ] 界面包含「什么是 Token？」折叠/引导卡片，清晰解答 Token 来源与三种场景的使用方式；
- [ ] 「高级设置」仅保留反代路径及静态手动 Token 输入；
- [ ] 单测全部覆盖并通过，无 lint/typecheck 错误。
